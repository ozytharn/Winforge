# Changelog

## Unreleased

- Added a design-only Action Broker V2 architecture, security/threat analysis, IPC identity and request-binding protocol, crash-recovery lifecycle, and phased implementation plan. Proposed ADR 0012 records the restricted demand-start service + local authenticated named-pipe recommendation; it is not accepted or implemented. V1 remains simulation-only, and no service, IPC, elevation, real executor, Windows-changing operation, migration, or modification to ADRs 0001–0011 was introduced.
- Completed Action Broker release-readiness remediation: only consume approval after the durable `started` journal write succeeds, preserve the actual simulation result when a subsequent journal refresh fails, and make preview policy/effects plus simulated verification/rollback explicit in the WPF UI. Corrected the roadmap's stale "no runtime broker" status and documented the simulation-only release verdict, recovery semantics, and unresolved identity/journal/forced-termination limitations. No real Windows-changing execution or migration was added.
- Added the Action Broker Core V1 simulation engine and WPF workflow integration: typed action catalog, preview-bound approval, deny-by-default validation, replay blocking, isolated simulation state, execution journal persistence, verification/rollback semantics, and a read-only Action Broker tab in the desktop shell. No real system-changing executor, privileged helper, or Windows mutation path was introduced.
- Completed an independent Action Broker security audit and simulation-only remediation: exact request/approval binding, typed normalized parameters and target consistency, serialized one-time execution with restart interruption recovery, fail-closed atomic journal persistence, WPF cancellation/shutdown handling, and focused security/UI tests.
